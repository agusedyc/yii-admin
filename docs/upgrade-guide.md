# Upgrade Guide: yii2-mimin (Yii2) → yii-admin (Yii3)

`agusedyc/yii-admin` is a **non-backward-compatible** port of `agusedyc/yii2-mimin`.
This document explains what changed, how the data maps, and how to migrate an existing
Yii2 mimin deployment.

## 1. High-level concept mapping

| Yii2 (yii2-mimin) | Yii3 (this package) |
| --- | --- |
| `yii\rbac\DbManager` (`authManager`) | `Yiisoft\Rbac\ManagerInterface` (built by the app) |
| `Yii::$app->user->can($route)` | `AccessCheckerInterface::userHasPermission($userId, $permission)` |
| `Yii::$app->allowActions` (global) | `agusedyc/yii-admin)['allowRoutes']` config array |
| `agusedyc\mimin\components\Mimin::checkRoute()` | `Agusedyc\Admin\Access\AccessService::checkRoute()` |
| `Mimin::filterMenu()` | `Agusedyc\Admin\Access\MenuFilter::filter()` |
| `Mimin::filterActionColumn()` | `Agusedyc\Admin\Access\ActionColumnFilter::filter()` |
| `components\AccessControl` (action filter) | `Agusedyc\Admin\Middleware\AccessMiddleware` (PSR-15) |
| `mimin` module (URL `?r=mimin/...`) | `/admin` route group (configurable) |
| `route` table (`name`, `alias`, `type`, `status`) | `{{%admin_route}}` (`pattern`, `methods`, `group_name`, `alias`, `status`) |

## 2. Schema mapping

### `auth_item` → `yii_rbac_item`

```sql
-- Yii2
auth_item (name PK, type INT 1|2, description, rule_name, data, created_at, updated_at)

-- Yii3
yii_rbac_item (name PK VARCHAR(126), type VARCHAR(10), description VARCHAR(191),
               rule_name VARCHAR(64), created_at INT, updated_at INT)
```

- `type` `1` → `'role'`, `type` `2` → `'permission'`.
- The `data` column no longer exists. Rules receive parameters at check time instead of the data
  string. Any data you relied on must be converted into a `Yiisoft\Rbac\RuleInterface` class.
- `name` length changed from `64` to `126`.

### `auth_item_child` → `yii_rbac_item_child`

Same shape: `(parent, child)` composite primary key. No translation needed.

### `auth_assignment` → `yii_rbac_assignment`

Same shape: `(item_name, user_id, created_at)`. `user_id` was a `string` in Yii2 as well.

### `route` → `admin_route`

```sql
-- Yii2
route (name PK VARCHAR(64), alias VARCHAR(64), type VARCHAR(64), status SMALLINT)

-- Yii3 (package migration)
admin_route (name PK VARCHAR(126), pattern VARCHAR(191), methods VARCHAR(64),
             group_name VARCHAR(64), alias VARCHAR(126), status SMALLINT,
             created_at INT, updated_at INT)
```

- `type` (controller id) → `group_name`.
- `pattern` / `methods` should be regenerated by `admin:sync`.

## 3. Migration SQL (PostgreSQL)

Run `yiisoft/rbac-db` migrations first (they create the empty `yii_rbac_*` tables), then insert
the legacy data:

```sql
-- Items
INSERT INTO yii_rbac_item (name, type, description, rule_name, created_at, updated_at)
SELECT name,
       CASE type WHEN 1 THEN 'role' WHEN 2 THEN 'permission' END,
       description,
       rule_name,
       COALESCE(created_at, extract(epoch from now())),
       COALESCE(updated_at, extract(epoch from now()))
FROM auth_item;

-- Relations
INSERT INTO yii_rbac_item_child (parent, child)
SELECT parent, child FROM auth_item_child;

-- Assignments
INSERT INTO yii_rbac_assignment (item_name, user_id, created_at)
SELECT item_name, user_id::text, COALESCE(created_at, extract(epoch from now()))
FROM auth_assignment;

-- Route metadata (baseline; pattern/methods will be filled by admin:sync)
INSERT INTO admin_route (name, pattern, methods, group_name, alias, status, created_at, updated_at)
SELECT name, '', '', type, alias, status,
       extract(epoch from now()), extract(epoch from now())
FROM route;
```

> `data` from `auth_item` is intentionally dropped — see §2.

## 4. Behavior changes to be aware of

1. **Permissions are named after routes.** In Yii2, permission names were URL *paths*
   (`/site/index`). With Yii3 the permission name is the **route name** (`site/index`), which is
   what `CurrentRoute::getName()` returns. Names are matched without the leading slash.
2. **No `*`-wildcard permissions.** The `/*` and `/controller/*` permissions used by
   `Mimin::checkRoute()` are replaced by the RBAC group hierarchy. Assigning a group permission
   (e.g. `post`) grants all of its children (`post/index`, `post/create`, …).
3. **Disabled routes block access regardless of RBAC.** `AccessService::checkRoute()` returns
   `false` for a route whose `admin_route.status = 0`, even when the RBAC permission is still
   assigned. Use this instead of deleting permissions to keep history/assignments safe.
4. **Guest access.** There is no default "guest" role. Add a `guest` role and use
   `Manager::setGuestRoleName('guest')` if you need guest permissions (view the
   [yiisoft/rbac README](https://github.com/yiisoft/rbac)).
5. **User management is out of scope.** The Yii2 mimin `User` CRUD is removed. Role-to-user
   assignment is done through `yiisoft/rbac` (`Manager::assign()`).

## 5. Bootstrapping the new hierarchy

After migrating the raw data, run the initial synchronization to create group permissions,
parent-child relations and the `pattern`/`methods` metadata:

```shell
./yii admin:sync
```

## 6. Slow migration from a live Yii2 app

1. Freeze writes to `auth_*` and `route`.
2. Run the SQL above in a transaction.
3. Run `admin:sync`.
4. Assign roles to users (`assign('role', $userId)`).
5. Enable `AccessMiddleware` and iterate on `allowRoutes`.
